    Controlled numerical experiment · no neural network

    Float32 versus float64 storage drift

    These runs use the same Rheon algorithm, pressure solver, tolerances, forces and initial state. Only velocity and tracer storage changes between float32 and float64. Pressure and intermediate arithmetic remain float64 in both. The trajectories separate from step one, without a shared warm-up. This isolates storage-precision effects from training error and differences between solvers.

    Accumulated field difference

    Independent float32 and float64 trajectories. A repeated float64 run is the null control: its field difference is exactly zero at every recorded step.

    Local storage rounding · identical inputs

    Each stage is replayed on the same inputs. These curves measure the actual difference between its float64 result and the stored float32 value. Projection also uses identical pressure. They exclude accumulated trajectory differences.

    Projection divergence · before and after storage rounding (s⁻¹)

    The third curve directly measures divergence of the casting perturbation, D(q32 − q64). It is calculated from the velocity fields, not by subtracting the two maximum-divergence values.

    Method, qualification and limits

    All voxels are cubic. At every step the instrumented float32 path matches Rheon’s original pressure, velocity and tracer buffers bit for bit, and the two float64 runs match each other exactly. Every measured local cast is checked against the original float32 result. The one-minute probe streams scalar measurements without retaining full-frame histories; the trajectories continue uninterrupted.

    Float64 is a comparison, not exact real arithmetic. Accumulated differences include subsequent responses to rounding, including possible changes in pressure-iteration paths under the same stopping policy. These curves are not a universal float32 accuracy floor and cannot be subtracted from scalar AI drift to determine a training-error percentage. This is not a comparison of float32 versus float64 neural-network inference.

Earlier recordings use the common cell-zero gauge; Pressure Methods IV–VI removes each pressure field’s spatial mean and retains exact full-field absolute/reference norms. Each recording states its gauge. Relative L2 error equals absolute RMS error divided by reference RMS magnitude; comparisons and normalization retain that recording’s gauge.

    The older drift recorder saved only relative error. Where newer same-request comparison norms are available, the Pa curves are bounded estimates for the independent trajectories; shaded bands and tooltips show their bounds. The same-request error itself is not plotted as drift. Missing measurements leave gaps and never become zeros.

    Method: let e be independent relative error, D the same-request absolute L2 error, and B = D / same-request relative L2 error. The independent reference L2 norm is bounded by max(0, B − D) / (1 + e) and (B + D) / (1 − e), for e < 1. Divide by √cell count to obtain RMS Pa; multiply by e to bound absolute drift. Bounds use recorded floating-point norms.

    How spatial frequency is calculated
    The saved cosine mode has frequency kᵢ / (2 Nᵢ h) cycles per metre along axis i. Each pattern’s X-axis position is the RMS spatial-frequency magnitude weighted by nonconstant pressure-mode energy. Duplicate modes are combined before weighting; constant pressure offsets are excluded. A single frequency summarizes each mixture, while its complete mode vectors and weights remain in the tooltips and source records. Cycles per cell removes the physical cell-size factor.
