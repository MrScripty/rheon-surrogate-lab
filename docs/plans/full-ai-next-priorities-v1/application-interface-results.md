# Application deployment and metric interfaces

Twelve deployment cases pass using actual independently trained K2/K3/K4
checkpoints: float64 and float32-map policies, each on steady and forcing-event
48-step episodes in one declared odd-grid development scene. Every consumed
state receives the original deferred equation/P/V/T and physical diagnostics.
The model retains its exact managed neural weights and normalization; no native
numerical advance enters forecast consumption.

This is a limited interface qualification. It does not establish all-eight-scene
own240accuracy for a new precision policy, CPU speed or application acceptance.
A generic deployment evaluator and evidence guard require actual complete
accuracy for the selected weights and policy before measurement admission.

Six native-control cases also pass: PCG and the spectral reference complete
both48-step scenarios and match checkpoint diagnostics. The real C107callback
runs and its unchanged first-step native rejection is retained. No fallback is
inserted and no completed throughput is assigned to rejected intervals.

The five-repeat application controller and report code are prepared. They need
a concrete frozen seven-method registry (K1/2/3/4plus three native controls),
actual accuracy/execution evidence, sources and reference identities before
running. They measure steady240and interaction48episodes, defer offline metrics,
and report discarded work, process custody, setup and memory separately.
