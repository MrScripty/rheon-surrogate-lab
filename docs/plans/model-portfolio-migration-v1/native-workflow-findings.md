## Boundaries for the next native views

Source inspection after the history gate identifies two separate integration
tasks. The existing `static/experiment-lineage.js` owns a complete Workbench
workflow, including branching and intent authoring. Its layout/graph rendering
can be shared, but its current API, catalog and mutation assumptions cannot be
reused unchanged for imported history. `project_files.lineage` currently returns
exact historical Trial sidecars, not the richer Study/attempt nodes consumed by
that renderer. The native page also supplies the current project UUID for this
query, which excludes the imported original catalog. Add an explicit origin
selector and a bounded read-only node projection from the retained history;
share the visual component through an adapter with appropriate historical
actions. Original namespace/Trial/material references remain exact. Read saved
outcomes without treating them as newly verified evidence or restoring grants.
The C106/C107 example has no recorded Trial lineage: the graph must show unknown
ancestry, not draw a relationship from chronology or relative accuracy.

The existing `static/retained-analysis.js` is explicitly a classifier view. It
requires frozen validation examples with truth/predicted class indices,
confidence, boolean error and a pinned checkpoint-curve recipe. Its contract
does not represent pressure/equation/velocity/tracer errors or heterogeneous
grid/cadence/device timings. Do not encode CFD results as classifier confidence,
invent a Tuldok Run for direct CLI benchmarks, or wrap scalar benchmark rows as
physical voxel fields. The next scalar comparison needs its own typed retained
measurement source/query and a host-owned chart recipe, using the existing
native data/artifact/selection lifecycle and renderer infrastructure.

First prove the scalar view with the retained common-request C106/C107 pressure
and equation results. Keep metric definitions, reference epoch, exact population,
grid dimensions, cells/metre, physical timestep, K, actual internal work, device,
precision and timing scope attached to every comparison. Missing fresh timings
remain missing; the first accuracy view cannot fabricate speed points. Failures,
unsupported domains and consumed/development cases stay visible. Drill-down
must return exact original case identities and values. Extend the shared view
only after real import, native comparison and independent cold reads pass.

Trial-free fits and prototypes remain a separate model/provenance representation.
The Trial tree alone is not the portfolio denominator. Their cards and declared
checkpoint/source derivations need native representation without fabricated
historical Trials, admissions or intent. Complete these two view seams before
expanding import across the full reconciled model inventory.
