## Tuldok workflow overhead

Owner: Tuldok execution/experiment workflow. Disposition: measured in this screen;
server optimization is separate from model training and must preserve current
authorization, source/material identity and custody checks.

C61 restore preflight took 241.412 seconds while another CUDA run was active;
C60 restore preflight took 113.271 seconds. Frequent known-ID `runs.get` calls
also take seconds. These are operation wall times, not a proved internal CPU
profile or a causal contention experiment. No server source or deployment is
changed during the matched screen. Typed calls, whole workflow and verified-byte
reuse are retained separately; direct owner/raw approval calls are not timed
individually by the current client profile. A later request-level profile should
identify repeated pure material/lineage validation within one authorized call
before selecting caching or concurrency changes.

## Broader manufactured coverage exposes an eight-pass gap

Owner: pressure model qualification. Disposition: new regression population,
reported separately from the 128 consumed real requests. Do not extrapolate the
earlier 128/128 result to every shape/mode.

neither qualifies any at four passes. Cubic voxel spacing and density/timestep are
unchanged. Original untouched holdouts remain unopened. This screen includes a
manufactured eight-pass guard as well as the real-request gates.
