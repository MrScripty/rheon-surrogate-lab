# Current-policy correction states

`prepare.py --root ROOT --config configs/preparation.json --output NEW_DIRECTORY`
freezes training-only prefixes from the selected CPU-restored checkpoint.
`--fixture` selects one real and one admitted analytical state. The exact captured
checkpoint inputs and source helpers are measured; no alternative dataset is
accepted by parent-count coincidence. Sixteen one-thread workers, bounded inflight
work, explicit memory reservation, runtime memory checks, separable transforms and
worker drainage retain OOM headroom. Output paths resolve under the selected root.

`freeze_bank.py --root ROOT --preparation QUALIFIED_DIRECTORY --output NEW_DIRECTORY`
checks every native pair hash and freezes the existing paired direction-bank
format. Gain1 preserves actual amplitudes. Both early/late stages use identical
cases, grids and sampling order. Labels use the independent spectral/neighbor
stencil oracle; no new fluid simulation is required. Captured arrays remain
external artifacts, never committed.

The v11 configuration adds one current_feedback stream to the existing real,
analytical, supplemental and older direction streams. It reuses the current
paired-bank loader, lineage/normalization and combined-residency checks. Stage
selection is the only scientific difference between configs/early.json and
configs/late.json. The current Project builder is
`../pressure-throughput-feedback-v1/assemble.py --current-bank BANK ...`.
The older project builder rejects v11 explicitly. Scheduling, CUDA/CPU custody,
SDK evidence, inference and all physical acceptance contracts retain their
existing owners. Historical captured sources remain immutable.

Use the existing run_study.py with configured root alias current-lab and the
original Tuldok catalog. Never replay uncertain mutations. Qualify fresh CPU
restores/first frames and all74development scenes before any untouched validation.
See docs/plans/pressure-current-policy-v1 for decisions, clocks and results.

`common_rhs.py` measures retained checkpoints on the exact qualified native pairs
from preparation, with independent labels and matched RHS. It is CPU preparation,
not a simulation or optimizer. Its concurrent clocks are not inference latency.
`compare_arms.py --root ROOT --reference RETAINED_STUDY --early EARLY_STUDY --late
LATE_STUDY --output NEW_REPORT` verifies actual CUDA/CPU artifacts and the allowed
bank-stage difference. It binds inspected configuration/source to the actual
Run closure and keeps numerical parity separate from accuracy qualification.
